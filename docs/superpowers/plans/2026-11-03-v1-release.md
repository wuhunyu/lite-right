# LiteRight v1.0.0 Unnotarized Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Merge the accepted LiteRight 1.0.0 UI and Finder fixes, tag the resulting main commit v1.0.0, and publish a non-prerelease GitHub Release with honest unnotarized ARM64 installers and checksums.

**Architecture:** Retain the existing unsigned local-URL transport intentionally because Developer ID signing/App Group are unavailable. Switch the display channel from preview to release for the production artifact only; preserve preview builds and their tests. Publish a tag and release through a narrowly scoped GitHub Actions workflow triggered by an explicitly marked main merge commit.

**Tech Stack:** Swift 6, XcodeGen, macOS 27 runner, shell scripts, GitHub Actions/GitHub CLI.

## Global Constraints

- User-authorized community release has an ad-hoc signature; do NOT claim Developer ID signature, notarization, or verified Finder Sync authorization.
- Git tag: `v1.0.0`; Info.plist `CFBundleShortVersionString=1.0.0`, `LiteRightReleaseChannel=release`, numeric `CFBundleVersion`.
- Existing preview workflow retains `1.0.0-preview`, `LITERIGHT_UNTRUSTED_PREVIEW` and the local URL validation.
- Only source commits on `main` may be tagged and released; the release bundle must be built from exactly the tagged commit.
- No change to the four Finder actions, window lifecycle, or their tested behavior.
- User must be given installation risk warning, checksums and current limitations, especially the one unresolved hosted GUI settings-persistence test.

# 01. 产品需求与业务规则

## 1. 产品定位与范围

**LiteRight**：macOS 27 上的轻量、纯本地、原生 Finder 右键增强工具。首版只实现五个平铺菜单项：

1. 新建文本文件（.txt）
2. 新建 Markdown（.md）
3. 切换显示隐藏文件
4. 在所配置的终端中打开
5. 复制目录路径

仅对 LiteRight 自己的五项菜单排序和显隐；不尝试篡改 Finder 系统菜单顺序，不注入 Finder 私有进程，不关闭 SIP，不提供 WebView/Electron UI，不上传任何本地文件。

## 2. 目录定位规则（强制统一）

| 场景 | 新建 TXT/Markdown | 显示隐藏文件 | 在终端打开 | 复制目录路径 |
|---|---|---|---|---|
| Finder 空白处，当前目录 D | D | 切换 Finder 全局状态；请求源为 D | D | D |
| 单选普通文件 D/a.py | D | 全局开关 | D | D |
| 单选文件夹 D/sub/ | D/sub/ | 全局开关 | D/sub/ | D/sub/ |
| 多选普通文件且同属 D | D | 全局开关 | D | D |
| 多选文件夹 / 文件，解析后目录不一致 | 禁用 | 可显示全局切换 | 禁用 | 禁用 |
| macOS 搜索结果选中文件 | 文件真实父目录 | 全局开关 | 文件真实父目录 | 文件真实父目录 |
| 搜索/最近使用空白处，无文件目录 | 禁用 | 可显示全局切换 | 禁用 | 禁用 |

统一算法：首先区分 Finder contextualMenuForContainer、contextualMenuForItems；文件用父目录，真实文件夹使用自身；.app 等包和符号链接默认为文件对象（避免在包内部操作、避免越过链接）；所有目标标准化；多选时只允许同一目录。路径必须是 file://，目录不存在或已卸载时禁用操作。

显示隐藏文件本质是 Finder 级视图开关；虽然从目录右键入口触发，但**不能承诺只对 D 生效**。

## 3. 文件名冲突与原子创建

| 第 N 次成功创建 | 文本 | Markdown |
|---:|---|---|
| 1 | untitled.txt | untitled.md |
| 2 | untitled_copy.txt | untitled_copy.md |
| 3 | untitled_copy_2.txt | untitled_copy_2.md |
| 4 | untitled_copy_3.txt | untitled_copy_3.md |

使用 open(O_CREAT | O_EXCL | O_WRONLY | O_CLOEXEC)，由底层文件系统原子判定冲突：禁止覆盖，禁止先 fileExists 再 write 的竞态写法，禁止仅调用 touch。当候选被其他并发创建抢占时继续尝试下一个候选；最多 10,000 次，否则明确失败。权限和空间错误立即结束。空白 TXT/Markdown 内容为零字节。

创建成功默认不自动弹窗、不自动打开编辑器。为了保持稳定，首版也不自动进入 Finder 重命名状态；可作为后续功能讨论。

## 4. 终端行为

- 终端应用：系统 Terminal.app（bundle com.apple.Terminal）、iTerm2（bundle com.googlecode.iterm2）。bash、zsh 是 Shell，不是终端应用。
- 启动时使用 NSWorkspace 识别是否已安装，设置中只允许选择真实可用的终端。卸载后将 UI 标记为不可用；点击操作时提示用户显式切换到 Terminal.app，不暗中替换配置。
- 菜单标题动态显示「在 Terminal 中打开」或「在 iTerm2 中打开」。
- 每次打开新的 Window，不能复用 Tab；继承终端默认 profile 和登录 Shell，用户可另选 bash 或 zsh。
- 创建 Window 后执行 cd -- '安全转义后的目录' && clear，失败必须可见且不能伪报成功；优先避免短暂显示上一工作目录。clear 是清理可视屏幕，不承诺清除全部滚动历史。
- 目录名可包含中文、空格、单/双引号、美元符、Tab、换行。脚本通过 Process.arguments 传入路径、由 AppleScript quoted form of ... 产生 shell 字面量，不拼接未过滤的输入。
- 在权限被拒绝、目标目录已被删除、终端不存在、脚本退出异常时给出明确操作建议。Terminal.app 的 Window/Tab 行为受系统偏好影响，阶段 2 需重点验证。

## 5. 隐藏文件切换

- 首版提供两条可配置路径：默认采用 AppleShowAllFiles 设置方式，展示“修改后需要重新启动 Finder”的提示，只有用户确认才重启 Finder；可选快捷方式模拟 Command+Shift+Period，需要辅助功能权限并检查 Finder 是否前台。
- 图标文案依据读取到的真实 Finder 全局显示状态切换「显示隐藏文件」/「隐藏隐藏文件」。读取失败时使用通用「切换隐藏文件显示」，不得猜测当前状态。
- 不修改任何文件的 hidden 属性，不在文件名首部增删 .，不擅自改变 iCloud 文件的同步状态。

## 6. 设置窗口与外观

- 纯 SwiftUI Settings / AppKit 原生 NSMenu。遵循系统深浅色、高对比度、降低透明度。使用系统 Liquid Glass，不绘制自定义后台模糊动画。
- 五个页面：右键菜单、终端、通用、权限管理、关于。窗口紧凑，不出现首次使用向导之外的繁杂弹窗。
- 菜单页：五个独立项目均支持可视化拖动排序、显隐开关、恢复默认。首版明确不使用二级子菜单。用户调整后，下一次构建菜单读取共享偏好，通常无需 Finder 重启。
- 仅控制 LiteRight 提供的菜单项；Finder 整体排序和一级菜单具体插入位置由系统决定。
- 原生菜单栏图标默认显示、可以隐藏；Dock 默认隐藏；主应用即使图标全部隐藏也可通过 Spotlight 再次打开设置。
- 登录自启默认关闭，使用 SMAppService.mainApp，不写 ~/Library/LaunchAgents。
- 关于页显示名称 LiteRight、App/Build 版本、系统要求、GitHub、离线隐私说明、诊断信息复制入口。

## 7. 权限与失败反馈

| 场景 | 首版 UX | 不允许的行为 |
|---|---|---|
| Finder Sync 关闭 | 显示扩展状态和前往系统设置引导 | 静默修改系统安全设置 |
| 自动化授权未给予 | 首次真正打开终端时触发 Apple Events 系统请求；拒绝后显示系统设置位置 | 反复弹窗 / 将 sudo 作为方案 |
| 文件夹写入被拒 | 提示目标目录不可写，支持文件夹选择器重新授权（若架构允许） | 请求完全磁盘访问作为通用先决条件 |
| 辅助功能未授权 | 快捷切换模式告知授权失败，仍可选基本方式 | 在用户未操作时偷偷发送键盘事件 |
| EEXIST | 自动换下一个候选名称 | 覆盖已有文件 |
| ENOSPC / EROFS / EACCES | 显示空间不足 / 只读 / 权限原因 | 自动重试直至锁死 |
| 终端启动成功但 cd 失败 | 留下可见错误，并提示实际当前路径 | 立即宣告“已进入目标目录” |
| Finder 扩展崩溃或任务超时 | 记录 request ID，先核实创建结果再决定重试 | 重复创建 _copy 文件 |

## 8. 性能与隐私验收

Finder 菜单创建 P95 <= 30ms；路径复制 P95 <=50ms；本地 APFS 上创建空文件 P95 <=100ms；扩展空闲 CPU 十分钟均值 <=0.1%；扩展单进程常驻内存目标 <50MB。以上均是测试门槛，需真机 Instruments 复测，终端本体启动时延不计入文件操作耗时。

无需数据库、网络服务、文件内容扫描、长期轮询、持续窗口渲染、后台遥测，主应用在无窗口/无状态栏/无请求时可退出。
